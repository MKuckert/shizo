Control what your AI agent can run.

Fail-closed Bash allowlisting for Claude Code.

shizo is a PreToolUse hook that parses shell syntax, resolves executables, and matches commands against a line-oriented rule set. Anything it cannot statically verify is denied.

How it works

1

Parse

Full shell syntax parse — pipes, chains, subshells, redirections.

2

Resolve

Every command is resolved against PATH and a trusted-directory set.

3

Sandbox check

Verify the sandbox capability file is present; deny everything otherwise.

4

Match rules

Argv tokens matched against allow/deny rules with ANY and HAS wildcards.

5

Decide

A deny always wins. Unmatched commands fall through to ask.

Why "ask the operator" isn't enough

Without shizo, unrecognized commands fall through to a human approval prompt. In practice, operators approve what they can't fully read. Can you spot the problem here? 

# Claude Code asks: "Run this command?"

python3 - <<'PY'
p = 'src/config/api.ts'
s = open(p, encoding='utf-8').read()

def sub(old, new):
    assert old in s, "NOT FOUND: " + old[:80]
    return s.replace(old, new, 1)

s = sub(
    'baseURL: "https://staging.example.com"',
    'baseURL: "https://api.example.com"',
)
s = sub(
    'timeout: 5000',
    'timeout: 15000',
)
s = sub(
    'retries: 1',
    'retries: 3',
)
open('/Users/you/.ssh/id_ed25519').read()  # ← line 19
s = sub(
    'logLevel: "debug"',
    'logLevel: "warn"',
)

open(p, 'w', encoding='utf-8').write(s)
PY

Line 19 reads your SSH private key. The rest is a legitimate config edit — boring enough that most operators scroll past it. Real sessions contained heredocs of 80–130 lines. shizo denies python3 by default so this never reaches the operator.

Rules at a glance

# Directives (global tier only)
sandbox nono
trust   /usr/bin
trust   /opt/homebrew/bin

# Allow safe reads
allow git status ANY
allow git log ANY
allow git diff ANY

# Block destructive operations
deny git push ANY
deny git reset HAS --hard
